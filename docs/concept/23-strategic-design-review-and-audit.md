## 2. Visual & Technical Assumptions Audit (Requirement 6)

### 2.1 Resolution, Scaling & Proportions Audit (`480×270`, `4×`, `16×16`, `16×24`)

The default visual lock (`480×270`, `16×16` tiles, `16×24` astronaut) remains our **recommended starting default** — *not* an unquestioned dogma. Every real trade-off below MUST be verified inside a **Playable Visual Prototype** before production art begins:

| Visual Spec | Real Strength | Real Unexamined Risk / Trade-Off | Mandatory Playable Visual Prototype Check |
| --- | --- | --- | --- |
| **`480 × 270` Native Canvas** | Exact `4×` integer scale on `1080p` (`8×` on `4K`); ~75% smaller hand-painted pixel area than HD pixel art; classic painterly intimacy (*Hyper Light Drifter*). | **Does NOT integer-scale cleanly to `1440p` (`5.33×` — one of the most popular PC monitor resolutions!) or Steam Deck (`1280×800`, `2.67×`)!** At `1440p`, strict integer `5×` (`2400×1350`) leaves black borders unless using fractional sharp-bilinear/texel-AA scaling or overscan. | Build a side-by-side **Windows Visual Prototype Gate** comparing **`480×270` (with overscan smooth-camera / sharp-bilinear at 1440p)** vs. **`640×360`** (`3×` exact to `1080p`, **`4×` exact to `1440p`**, `6×` exact to `4K`, at `1.78×` pixel art area cost). Lock final resolution ONLY after seeing real motion on actual displays! |
| **`16 × 16` World Tile Grid** | Crisp, manageable autotiling; fast shoreline & cliff iteration; low VRAM footprint. | Easy to fall into boxy "RPG Maker grid" feel if straight edges dominate; organic diagonal cliffs and sweeping curved rivers require rich overlapping multi-tile props & edge-decals. | Test 1 real painted Rimlands coastal cove + reedwood grove strip at `100%` scale to confirm zero visible tile-grid monotony. |
| **`16 × 24` Astronaut Sprite** | `~9%` of viewport height evokes genuine Ghibli-scale solitary awe beside `96–128 px` towering trees. | **Face is ~`4×4` pixels!** Zero micro-facial acting; narrow silhouette makes small handheld tools (*Knife* vs *Chime* vs *Bio-Dart*) hard to distinguish; easily occluded behind towering oblique 3/4 tree canopies. | Validate Mara's silhouette readability during movement, crouching, tool-swap poses, and canopy walk-behind translucency fade in real gameplay motion! Test whether `16×24` vs. slightly taller `18×28` reads better without sacrificing landscape grandeur. |
| **Pixel-Snapped vs. Smooth Sub-Pixel Camera** | Pure integer camera snapping prevents shimmer on static pixels. | Slow oblique diagonal walking at `480×270` on `60–144 Hz` monitors can appear visibly juddery/stuttery when snapped to 1 logical pixel (= 4–5 screen pixels!). | Implement and A/B test a **`482×272` overscan `SubViewport` smooth-camera shader** (sliding the upscaled viewport by the sub-pixel remainder!) on real `60 Hz` and `120+ Hz` Windows displays. |

### 2.2 Hybrid Handcrafted / Procedural World & Chunk-Streaming Reality Check

- **Hard Epistemic Firewall (`L4` Simulation != `L5` Godot Runtime Proof!)**:
  - `tools/world_chunk_simulator.py` verified **ONLY offline Python math**: that a `64×64` grid can protect `168` landmark cells with `0` spatial overlap, scatter `123` entities cleanly across separated flora/fauna Poisson layers, and serialize entity descriptors in `10.2 KB`.
  - It proves **NOTHING** about real Godot 4 runtime performance on Windows:
    - Real-time `TileMapLayer` scene instantiation & `PhysicsServer2D` broadphase spike when registering hundreds of terrain collision shapes during chunk entry.
    - `NavigationRegion2D` / obstacle avoidance rebuild latency when dynamic tidal water or storm obstacles change walkability.
    - VRAM atlas fragmentation across 12 biome tilesets + 1D LUT shaders + animated water reflection shaders.
    - Main-thread hitches during `ResourceLoader.load_threaded_get()` + `add_child()` node tree attachment.
- **Architectural Refinement for Pre-Production (`DDL-012`)**:
  - **For the Vertical Slice (`4×4 = 16` chunks)**: Do **NOT** build a complex general-purpose procedural continent generator! Use **author-composed macro chunk layouts** with **offline/editor-time ecological scatter assist**, keeping streaming architecture real (`3×3` active chunks) while guaranteeing 100% curated painterly composition and eliminating seam bugs between stamped Hero Landmarks and autotiled terrain!
  - **Transition Seam Mitigation**: Never stamp rigid rectangular Hero Landmark scenes directly over procedural tile grids. Author **irregular organic landmark silhouettes** with a `4–6` tile **feathered ecological blend collar** (ground decals, root/pebble scatter, shoreline bevels) so handcrafted vistas melt invisibly into surrounding mosaic tiles!

### 2.3 Windows Godot Environment Verification Mandate (Zero Engine Version Assumptions!)

- **Explicit Honesty Statement**: Earlier Phase 1–3 sandbox verification audited official Godot `4.7.2-stable` XML Class-Ref documentation cloned from GitHub because no Godot executable exists in this Linux sandbox.
- **Hard Pre-Production Rule**: **We do NOT claim that Godot `4.7.2` — or ANY specific Godot version — is installed on the user's Windows development machine!**
- Before creating `project.godot` or writing a single line of production GDScript (Stage 05 Step 0), the Windows setup check MUST directly verify and record:
  1. Actual installed Windows Godot binary version (`godot --version` or exact Editor version string) and `.NET` vs Standard build.
  2. Active renderer (`Forward+` Vulkan / `D3D12` vs `Compatibility` OpenGL) and actual Windows GPU/monitor resolution (`1080p`, `1440p`, `4K`, refresh rate).
  3. Whether any `4.4–4.7` API deltas (e.g., `@abstract`, `TileMapLayer` physics quadrant defaults, `AudioStreamInteractive` behavior) differ on the verified Windows Godot version — adapting templates cleanly before coding!
